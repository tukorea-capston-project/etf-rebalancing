# 전체 로직 설명

파일마다 들어 있는 필드는 [JSON 파일별 설명](json-files.md) 참고.

> 이 문서는 개편안(사용자 입력 우선 + HRP 생성 + 신호 기반 동적 리밸런싱) 기준임. 정해지지 않은 부분은 **잠정**으로 표시하고 맨 아래 [미결 사항](#미결-사항)에 모아 둠. 예시 JSON의 미정 값은 `null`, 예시 규칙은 `"status": "예시"`로 표시함.

## 한눈에 보기

| 단계 | 내용 | 관련 파일 |
|---|---|---|
| 1. 요청 해석 | 사용자 메시지를 LLM이 칸 단위로 해석 | `parse_request` |
| 2. 초안 채우기 | 사용자가 말한 값을 먼저 채우고, 문제(이슈)를 확인하고, 빈 칸은 기본값으로 채움 | `draft` |
| 3. 포트폴리오 생성 | 자산군 비중 → 사용자 지정 고정 → HRP로 종목·비중 계산 → 제한 확인 | `draft` |
| 4. 확인 | 사용자가 확인하면 포트폴리오가 됨 | `portfolio` |
| 5. 백테스트 | 같은 로직을 과거 시점으로 옮겨 실행. 고정비중·거시판단 두 결과를 보여 주고 사용자가 승인 | `backtest`, `adjustment` |
| 6. 운용 | 모의·실전투자. 정적 층(이중 밴드)과 동적 층(국면 신호)이 함께 돎 | `portfolio` |
| 7. 동적 리밸런싱 | 국면 신호가 기준을 넘으면 목표 종목·비중을 자동으로 바꿈 | `market` → `adjustment` → `portfolio` |

LLM은 **해석과 문장 작성만** 맡음. 포트폴리오 생성, 규칙 적용, 주문은 전부 서버 코드가 함. LLM 출력은 정해진 형식인지 검증한 뒤에만 씀.

**백테스트와 운용은 같은 로직**임. 백테스트는 기준 시점만 과거로 옮겨 [3]과 [6]·[7]을 그대로 돌림. 그래서 동적 리밸런싱은 사용자가 매번 고르는 방식이 아니라 자동 반영임. 사용자 선택은 과거로 재현할 수 없기 때문.

## 핵심 원칙: 사용자가 말한 값이 먼저

칸을 채우는 우선순위:

**안전 규칙 > 사용자가 말한 값 > 생성 > 기본값**

- 사용자가 말한 종목·비중은 시스템이 만든 값보다 항상 앞섬. 생성 로직은 남은 부분만 채움
- 다만 안전 규칙(선정 조건, ETF 하나 최대 비중 같은 제한)은 사용자 요청보다 위임

투자 성향(위험 성향)은 쓰지 않음. 사용자가 비중을 말하지 않으면 정책의 기본 자산군 비중을 씀.

## 핵심 개념

### 자산군(asset_class)

ETF를 성격별로 크게 묶은 단위. 주식, 채권, 현금성, 통화, 원자재, 리츠.

투자 대상 ETF는 선정 조건을 통과한 ETF임(루트 `CLAUDE.md`). ETF는 세부 분류(category)를 갖고, 카탈로그의 `categories`가 분류마다 자산군을 정해 줌. 분류는 기초지수명·종목명으로 정하는 규칙과 보정표로 매김(전환 전에는 화이트리스트에 사람이 적은 값).

| 종목코드 | ETF | 분류(category) | 자산군 |
|---|---|---|---|
| `360750` | TIGER 미국S&P500 | `foreign_equity_country` | 주식 |
| `148070` | KIWOOM 국고채10년 | `domestic_bond` | 채권 |
| `357870` | TIGER CD금리투자 | `cash_equivalent` | 현금성 |

자산군 비중(주식 몇 %, 채권 몇 %)이 포트폴리오의 위험 수준을 거의 정함. 그래서 자산군 비중은 사용자가 정하거나 기본값을 쓰고, 자산군 안의 종목·비중만 HRP가 계산함.

위험자산은 주식·원자재·리츠임(`catalog.risk_asset_classes`). 기간 경고에 씀.

### 기본 자산군 비중

사용자가 자산군 비중도 ETF별 비중도 말하지 않았을 때 쓰는 비중(`policy.defaults.asset_classes`). 잠정 **주식 60% / 채권 40%**.

기본값이 꼭 필요한 이유: HRP는 덜 출렁이는 자산에 비중을 더 주므로, 자산군을 넘어 한꺼번에 돌리면 채권·현금성이 거의 전부를 가져감. 주식과 채권을 몇 대 몇으로 둘지는 HRP가 정해 주지 않음.

### 칸(slot)과 출처

포트폴리오를 만드는 데 필요한 **정보 하나하나**. 목적, 기간, 투자금, 자산군 비중, ETF 목록 등이 각각 칸 하나임. 밴드 폭 같은 운용 규칙은 칸이 아니라 정책 값을 씀.

칸마다 값과 함께 **출처**를 저장함.

| 출처(`source`) | 의미 | 예시 |
|---|---|---|
| `사용자발화` | 사용자가 메시지에서 직접 말함 | "2년 뒤에" → 기간 24개월 |
| `질문답변` | `확인` 이슈 질문에 사용자가 답함 | 주식 비중 50%와 70% 중 → 70% |
| `생성` | HRP가 고른 종목·비중 | 채권 → 114260 35% |
| `기본값` | 정책의 기본값 | 자산군 비중 → 주식 60 / 채권 40 |

출처가 남아 있어서 확인 화면에서 "말씀하신 것 / 계산한 것 / 기본값"을 구분해 보여 줄 수 있음.

### 이슈 4단계

사용자 요청이 규칙에 어긋나면 **심각도 단계**에 따라 처리함. 규칙과 단계는 `policy.checks`에 모여 있음.

| 단계 | 처리 | 예 |
|---|---|---|
| `차단` | 담지 않고 이유를 알림 | 개별종목, 레버리지, 선정 조건 밖 ETF, 수익 보장 요구 |
| `조정` | 가장 가까운 가능한 값으로 서버가 고치고, 바뀐 부분을 보여 줌 | 비중 합계 110%, ETF 하나 70%(최대 50%) |
| `확인` | 서버가 혼자 정하지 않고 선택지를 줌 | 말한 비중끼리 안 맞음. "주식 50%"라면서 주식 ETF 비중을 더하면 70% |
| `경고` | 그대로 진행하되 경고를 붙임 | 2년 쓸 돈인데 위험자산 위주, 같은 묶음의 ETF 두 개를 함께 담음 |

`확인` 단계에서 질문을 3회(`max_question_rounds`) 하고도 정해지지 않으면, 나중에 말한 값을 기준으로 서버가 조정하고 그 내용을 보여 줌(잠정).

### HRP (Hierarchical Risk Parity)

자산군 안에서 **종목을 고르고 비중을 나누는** 방법. 상관계수와 변동성을 함께 씀(López de Prado, 2016). **처음 생성할 때만** 씀. 동적 리밸런싱에는 쓰지 않음.

| 용어 | 의미 |
|---|---|
| 변동성 | 가격이 평소에 얼마나 크게 오르내리는지. 일간 수익률의 표준편차를 연 단위로 환산 |
| 상관계수 | 두 ETF가 얼마나 같이 움직이는지. 1에 가까우면 거의 똑같이 움직임(예: S&P500과 나스닥 약 0.9) |
| 묶음(군집) | 상관계수가 높아 같이 움직이는 ETF끼리 묶은 것 |
| 역분산 | 변동성 제곱의 역수. 덜 출렁이는 ETF에 비중을 더 줌 |

계산 순서:

1. **군집 나누기**: 후보 ETF를 상관계수로 묶음. 같이 움직이는 ETF는 사실상 하나로 봄
2. **순서 정렬**: 비슷한 ETF끼리 붙도록 순서를 정함
3. **반씩 나누기**: 목록을 둘로 나누고, 덜 출렁이는 쪽에 비중을 더 줌(역분산). 이를 ETF 하나가 남을 때까지 반복

ETF가 두 개뿐이면 결과는 역분산 비중과 같음.

HRP를 쓰는 이유:
- 투자 대상에 KODEX 200과 200TR처럼 거의 같은 ETF가 많음. HRP는 이들을 한 묶음으로 봐서 한쪽에 쏠리지 않음
- 공분산 행렬의 역행렬을 쓰지 않아 비슷한 ETF가 많아도 계산이 안정적임
- 기대수익을 예측하지 않음. 수익 전망은 거시판단 로직이 따로 맡음

**HRP는 자산군 안에서만** 돌림([기본 자산군 비중](#기본-자산군-비중) 참고). 비교용으로 `역변동성`, `동일비중`도 설정값(`construction.weighting`)으로 남겨 백테스트에서 비교할 수 있게 함.

### 기준 비중(base)과 목표 비중(target)

| | 의미 | 바뀌는 때 |
|---|---|---|
| 기준 비중 `base` | [3]에서 만든 비중. 사용자 요청을 반영한 원래 구성 | 사용자가 포트폴리오를 직접 수정할 때만 |
| 목표 비중 `target` | 지금 맞추려는 비중 | 동적 층이 국면을 전환할 때 |

목표 비중은 누적해서 바꾸지 않고 매번 **기준 비중 + 지금 국면의 조정**으로 다시 계산함. 같은 국면이 몇 달 이어져도 조정이 쌓이지 않고, 국면이 원래대로 돌아오면 목표도 기준 비중으로 돌아옴. 같은 국면이면 같은 결과가 나오므로 백테스트에서도 그대로 재현됨.

### 두 층: 정적 층과 동적 층

운용 중에는 두 층이 함께 돎.

| | 정적 층 | 동적 층 |
|---|---|---|
| 하는 일 | 시장 움직임으로 벌어진 비중을 **목표 비중으로 되돌림** | 국면이 바뀌면 **목표 종목·비중 자체를 바꿈** |
| 감지 방식 | 이중 밴드 | 국면 신호 |
| 판단 근거 | 비중이 얼마나 벌어졌나 | 거시판단(국면 지표) |

두 층이 따로 움직이면 서로 거스를 수 있음. 예를 들어 밴드로 사들인 자산을 며칠 뒤 동적 전환에서 다시 팔면 거래비용을 두 번 냄. 그래서 [우선순위](#두-층의-우선순위)를 정해 둠.

### 동적 층: 달력이 아니라 신호로 감지

국면 지표를 **매일** 점검하고, **기준을 넘을 때만** 포트폴리오를 전환함. 정해진 날짜마다 바꾸지 않음.

| 국면 지표(예) | 점검 | 비고 |
|---|---|---|
| 변동성 | 매일 | 예: VKOSPI |
| 추세 | 매일 | 예: 지수의 이동평균 위·아래 |
| 금리 스프레드 | 매일 | 예: 장단기 금리차 |
| 국면 확률 모델 | 매일 | 예: 점프모형의 상승·하락 확률 |
| 경기·업종 지표 | 발표일 | 경기선행지수, 수출 등 월간 지표. 발표되는 날 갱신 |

어떤 지표를 쓰고 기준을 어떻게 정할지는 거시판단 로직에서 정함(추후 구현).

**기준값을 정하는 방식**: 진입·해제 기준과 그 간격은 백테스트 결과를 보고 고르지 않고, 관례값·기본값(예: Z-Score ±1, 분위수)을 근거와 함께 미리 정해 씀. 백테스트 결과에는 견고성 표와 과최적화 확률(PBO)을 함께 보여 줌. 상세는 `docs/backtest.md` [국면 판단 기준값과 과최적화](backtest.md#국면-판단-기준값과-과최적화).

**분기 날짜는 "최소 점검일"로만 남김.** 신호가 없어도 분기마다 한 번은 국면을 재평가함. 그 결과 국면이 그대로면 아무것도 바꾸지 않음.

**휩쏘(신호가 짧게 오락가락하며 매매가 반복되는 것) 방지**: 두 가지를 함께 씀.

| 방법 | 의미 | 예 |
|---|---|---|
| 진입·해제 기준 다르게 | 국면에 들어가는 기준과 빠져나오는 기준 사이에 간격을 둠 | 하락 확률 70% 넘으면 방어 국면 진입, 50% 아래로 내려와야 해제 |
| 확인 기간 | 신호가 정해진 기간 동안 유지될 때만 실행 | 기준을 넘은 상태가 3영업일 이어지면 전환 |

국면 전환이 정해지면, 실운용에서는 LLM이 뉴스·문서에서 근거를 확인함(`evidence_check`). 근거가 부족하면 전환을 보류함(`hold_until`).

### 정적 층: 이중 밴드

밴드를 두 겹으로 두고, 바깥 밴드 이탈은 **국면 변화의 경보**로도 씀.

| 이탈 | 처리 |
|---|---|
| 안쪽 밴드 이탈 | 정적 리밸런싱. 벗어난 자산만 목표 비중으로 되돌림 |
| 바깥 밴드 이탈 | 되돌리기 전에 **국면 재평가부터** 실행 |
| 같은 방향으로 반복 이탈 | 같은 자산이 같은 방향(계속 넘침, 계속 모자람)으로 정해진 횟수 이상 이탈하면 바깥 밴드 이탈과 똑같이 처리 |

국면 재평가 결과:
- 국면이 바뀌었으면 → 동적 전환. 새 목표 비중으로 맞춤. 정적 리밸런싱은 따로 하지 않음
- 그대로면 → 정적 리밸런싱

비중이 크게 또는 계속 한쪽으로 벌어진다는 건 시장 흐름이 바뀌고 있다는 신호일 수 있음. 이때 무조건 원래 비중으로 되돌리면 국면 변화를 거스르게 됨. 이중 밴드를 쓰면 밴드가 국면 변화를 거스르는 대신 감지 장치 역할을 함.

밴드 폭은 **절대 폭(%p)**과 **상대 폭(%)** 두 값으로 정하고, 둘 중 **좁은 쪽**을 씀(5/25형).

| 밴드 | 폭(잠정) | 목표 15%일 때 |
|---|---|---|
| 안쪽 | 5%p / 25% | 15% × 25% = ±3.75%p (5%p보다 좁음) → 11.25% ~ 18.75% |
| 바깥 | 10%p / 50% | 15% × 50% = ±7.5%p (10%p보다 좁음) → 7.5% ~ 22.5% |

밴드 확인은 국면 신호 점검과 같이 매일 장 마감 뒤에 함. 반복 이탈을 세려면 자산별 이탈 기록이 필요하므로 `portfolio.band_state`에 남김.

### 두 층의 우선순위

국면 신호가 **기준선 근처**(근접 구간)에 있으면 밴드 리밸런싱을 보류하고 동적 판단을 먼저 함.

| 국면 신호 | 밴드 이탈 시 처리 |
|---|---|
| 기준선에서 멂 | 이중 밴드 규칙대로 |
| 기준선 근처 | 밴드 리밸런싱 보류. 국면 판단이 나올 때까지(전환 또는 근접 구간 벗어남) 기다림 |

근접 구간의 폭은 신호마다 정함(`dynamic.near_threshold`, 잠정). 보류가 너무 길어지지 않게 최대 보류 기간을 둠(잠정). 보류 시작일은 `portfolio.band_state`에 남김.

### 레짐(regime)과 시장 분위기(mood)

| | 보는 것 | 상태 | 갱신 |
|---|---|---|---|
| 경기 레짐 | 경기선행지수, 금리, 환율, 수출 | 좋아짐 / 꺾임 / 나쁨 | 지표 발표일 |
| 업종 레짐 | 업종별 수출 증감률 | 늘어남 / 줄어듦 | 지표 발표일 |
| 시장 분위기 | 변동성, 신용융자, 예탁금, 뉴스 감성 | 공포 / 보통 / 탐욕 | 매일 |

업종 레짐은 매달 나오는 업황 지표가 있는 국내 업종(반도체IT, 2차전지, 자동차, 조선)만 대상임. 나머지 ETF는 경기 레짐으로만 판단함.

레짐은 동적 층의 국면 지표로 쓰이고, 시장 분위기는 비중을 바꾸지 않고 알림만 줌.

## 단계별 흐름

예시 파일들은 한 사용자의 흐름을 이어서 보여 줌. 아래도 그 예시로 설명함. **숫자(변동성, 비중)는 설명용 예시**임.

### [1] 요청 해석

사용자 메시지:

> 100만원 있는데 2년 뒤에 전세금 보탤 돈이에요. S&P 그거 넣어주시고 반도체도 조금 넣어주세요. 삼성전자도요

LLM이 `parse_request.json` 형식으로 해석함.

| 원문 | 칸 | 값 |
|---|---|---|
| "100만원" | 투자금 | 1,000,000 |
| "2년 뒤에" | 기간 | 24개월 |
| "전세금 보탤 돈" | 목적 | 주택자금 |
| "S&P 그거" | ETF | 360750 (별칭 "S&P") |
| "반도체도 조금" | ETF | 395270, 비중 표현 `조금` |
| "삼성전자도요" | 범위 밖 | 개별종목 |

- 값은 카탈로그에 있는 값만 쓸 수 있음. 형식이 틀리면 최대 2회 다시 요청함
- 원문을 `quote`로 남기므로, 서버가 메시지에 그 말이 실제로 있는지 확인할 수 있음
- ETF는 별칭(`aliases`)이나 종목명으로 찾음. 오늘 시점 선정 조건을 통과하지 못한 ETF는 담을 수 없음
- "주식 70%, 채권 30%"처럼 자산군 비중을 말하면 `asset_classes`에 담음

### [2] 초안 채우기

해석 결과를 `draft.json`의 칸에 옮기고 빈 칸을 채움.

1. **사용자가 말한 값을 먼저 채움**: 투자금, 기간, 목적, ETF 두 개(비중은 안 말함, 반도체는 `조금`)
2. **이슈 확인**: "삼성전자" → `차단`(개별종목)
3. **나머지는 기본값**: 자산군 비중(주식 60 / 채권 40). 출처를 `기본값`으로 표시

### [3] 포트폴리오 생성

사용자가 비중과 종목을 얼마나 정했는지에 따라 네 경우가 있지만, **같은 순서 하나**로 처리함.

1. **자산군 비중 정하기**: 사용자가 말했으면 그대로, 아니면 기본 자산군 비중
2. **사용자 ETF 비중 고정**: ETF별 비중을 말했으면 그대로 고정하고, 그만큼을 해당 자산군 비중에서 뺌
3. **군집 나누기**: 자산군마다 후보 ETF를 상관계수로 묶음. 후보는 사용자가 종목을 줬으면 그 종목들, 안 줬으면 그 시점에 선정 조건을 통과한 그 자산군의 ETF 전체(백테스트는 선정 시점, 운용은 오늘). 데이터 기간이 짧은 ETF는 자동 후보에서 뺌
4. **종목 고르기**: 사용자가 줬으면 그대로(같은 묶음끼리면 `경고`). 안 줬으면 묶음마다 대표 1개(변동성이 낮거나 거래량이 많은 것), 전체 최대 10개
5. **HRP 비중**: 자산군 안의 남은 비중을 HRP로 나눔. 비중 표현(`조금`·`보통`·`많이`)이 있으면 HRP 비중에 곱한 뒤 다시 합이 맞게 나눔(잠정: 0.5·1·1.5배)
6. **제한 확인**: ETF 하나 최대 50%·최소 5%, 1% 단위

| 경우 | 1 자산군 비중 | 4 종목 선택 | 5 비중 계산 | 난이도 |
|---|---|---|---|---|
| 둘 다 선택 안 함 | 기본값 | 묶음별 대표 | HRP | 보통 |
| 비중만 선택 | 사용자 | 묶음별 대표 | HRP | 보통 |
| 종목만 선택 | 기본값 | 사용자 | HRP | 쉬움 |
| 둘 다 선택 | 사용자 | 사용자 | - | 검사만 함 |

"S&P 30%, 나머지 알아서"처럼 섞인 요청은 2에서 S&P 30%를 고정하고 나머지는 그대로 처리함.

사용자가 종목만 주고 그 종목이 한 자산군에만 있으면(예: 주식 ETF만 말함), 다른 자산군은 기본 비중대로 HRP가 종목을 골라 채움.

**예시 (종목만 선택한 경우)**

① 자산군 비중: 기본값 → 주식 60%, 채권 40%

② 주식 60%: 사용자 ETF 두 개를 HRP(두 개라 역분산)로 나누고 비중 표현을 곱함

| ETF | 변동성 | 역분산 비중 | 비중 표현 | 반영 후 | 주식 60% 안에서 |
|---|---|---|---|---|---|
| `360750` S&P500 | 18% | 74% | 보통(×1) | 85% | **51%** |
| `395270` 반도체 | 30% | 26% | 조금(×0.5) | 15% | **9%** |

③ 채권 40%: 사용자가 안 정함 → 선정 조건을 통과한 채권 ETF를 군집으로 나누고 묶음별 대표를 뽑아 HRP로 나눔

| 묶음 | 대표 ETF | 변동성 | HRP 비중 | 최소 5% 적용 |
|---|---|---|---|---|
| 국내 단기채 | `114260` 국고채3년 | 2% | 36% | **35%** |
| 국내 장기채 | `148070` 국고채10년 | 6% | 4% | **5%** |

④ 제한 확인: 모두 50% 이하, 5% 이상 → 통과

기간이 짧은데 위험자산 비중이 높으면 `경고`를 붙임. 예시는 24개월에 주식 60%라 경고가 붙음.

### [4] 확인

서버가 확인 문장(`confirm_text`)을 만들어 보여 줌.

> 24개월 뒤 주택자금, 100만원으로 이해했어요. 주식 60%는 말씀하신 미국 S&P500과 국내 반도체(조금)로 담았고, 덜 출렁이는 S&P500에 더 많이 넣었어요. 채권 40%는 서로 다르게 움직이는 국고채 3년·10년으로 채웠어요. 운용 중에는 시장 국면에 따라 비중과 종목이 자동으로 바뀌어요. 주식이 60%인 구성은 3년 안에 쓸 돈이라면 손실 상태로 찾아야 할 수 있어요. 삼성전자 같은 개별 종목은 담을 수 없어요.

사용자가 확인해야만 `portfolio.json`이 만들어짐. 이때 계산한 비중이 기준 비중(`base`)이자 첫 목표 비중(`target`)이 됨. 단계(`stage`)는 `백테스트`.

### [5] 백테스트

[3]과 [6]·[7]을 **기준 시점만 과거로 옮겨** 그대로 돌림. 결과는 `backtest.json`에 남음.

| 실행 | 내용 |
|---|---|
| `거시판단` | 실제 운용 로직 그대로. 정적 층 + 동적 층. 기간 중 동적 전환 기록은 `adjustment.json`(`mode: 백테스트`)으로 남음 |
| `고정비중` | 비교용. 동적 층을 끄고 기준 비중을 유지하며 안쪽 밴드 리밸런싱만 함. 거시판단이 실제로 도움이 됐는지 보여 주는 기준 |

비교 대상: 리밸런싱 안 했을 때, KODEX 200만 샀을 때. 성과 지표는 [백테스트](backtest.md)를 따름(CAGR, 변동성, MDD, 샤프 지수 등).

**생성을 두 번 함**

HRP(생성 로직)는 같은 로직을 기준 시점만 바꿔 두 번 돌림.

| 언제 | 기준 시점 | 쓰는 데이터 | 용도 |
|---|---|---|---|
| [3] 처음 생성 | 오늘 | 오늘까지의 `lookback` 기간 | 실제로 운용할 포트폴리오 |
| [5] 백테스트 시작 | 백테스트 시작일 | 시작일까지의 `lookback` 기간 | 과거 검증용 포트폴리오 |

오늘 만든 포트폴리오를 그대로 과거에 돌리면, 백테스트가 그 당시에는 알 수 없던 정보(이후 몇 년간 어떤 ETF가 덜 출렁였는지)를 알고 시작하게 되어 결과가 실제보다 좋게 나옴(미래 정보 누설, look-ahead bias). 그래서 "그때 이 로직을 썼다면 어떤 포트폴리오가 나왔을까"를 시작일 기준으로 다시 계산함.

- 다시 계산하는 것은 HRP가 정한 부분(묶음, 대표 종목, 자산군 안 비중)뿐임. 사용자가 정한 종목·비중과 자산군 비중은 그대로 씀
- 그래서 백테스트 속 비중은 [4]에서 보여 준 비중과 조금 다를 수 있음. 결과 화면에 둘을 함께 보여 줌. 두 결과는 `backtest.json`의 `construction`과 `portfolio.json`의 `holdings`에 각각 남음

**시작일에 없던 ETF**

백테스트 시작일에 상장되지 않았거나 `min_history`만큼 데이터가 없는 ETF는 그 시점의 HRP 후보가 될 수 없음.

| 경우 | 처리 |
|---|---|
| HRP가 고르는 후보 | 그 시점에 데이터가 있는 ETF 중에서만 고름. 따로 처리할 것 없음 |
| 사용자가 고른 ETF | 백테스트 시작일을 그 ETF의 데이터가 충분해지는 날로 늦춤. 늦춘 결과 기간이 너무 짧아지면 그 ETF를 빼고 돌리고, 뺐다고 결과 화면에 표시함(잠정) |

**그 밖에 과거 시점 T에서 미래 정보를 쓰지 않는 규칙**
- **국면 지표**: 발표일(`released_at`)이 T 이전인 것만 씀
- **LLM 판단**: 잠정으로 백테스트에서는 쓰지 않고 지표 신호만 씀. LLM이 과거 뉴스의 그 이후 결과를 이미 알고 있을 수 있기 때문([미결 사항](#미결-사항))

나머지 가정:
- 주문은 다음 영업일 종가에 체결된다고 가정
- 가격은 실제 종가, 분배금은 같은 ETF에 재투자
- 수수료 0.015%, 슬리피지 0.1%, 세금은 ETF 유형별

사용자가 결과를 보고 승인하면(`approved_at`) 운용 단계로 넘어감.

### [6] 운용

KIS 계좌로 실제 주문을 냄. 모의운용과 실전운용은 같은 로직임.

**운용 시작 시점에 지금 국면을 바로 반영함.** 기준 비중은 국면 조정이 없는 비중이므로, 운용을 시작하는 날 이미 어떤 국면에 있다면 첫 목표 비중은 기준 비중 + 그 국면의 조정임. 백테스트도 시작일의 국면을 같은 방식으로 반영함.

- 주문은 장 시작 전 동시호가(08:40)에 냄. 1만원 미만 주문은 내지 않음
- 주문 전 점검: ETF 가격이 NAV보다 1% 넘게 비싸면 보류, 거래정지 종목 건너뜀, 잔고 확인
- 적립금이 들어오면 목표보다 부족한 자산부터 삼

매일 장 마감 뒤 한 번에 점검함.

1. **국면 신호 점검**: 기준을 넘고 확인 기간을 채웠으면 → [7] 동적 전환
2. **밴드 점검**: 동적 전환이 없을 때만
   - 국면 신호가 기준선 근처면 → 밴드 리밸런싱 보류
   - 바깥 밴드 이탈 또는 같은 방향 반복 이탈 → 국면 재평가. 바뀌었으면 [7], 그대로면 정적 리밸런싱
   - 안쪽 밴드 이탈 → 정적 리밸런싱
3. **분기 최소 점검일**이면 신호가 없어도 국면 재평가

정해진 주문은 다음 날 장전 동시호가에 냄. 주문 직전 이상 감지와 사용자별 긴급 중지는 [모의·실전투자](trading.md)를 따름. 자동 주문이 정지된 동안에도 국면·밴드 점검은 계속하고 기록만 남김.

**포트폴리오 직접 수정**: 사용자가 종목·비중을 바꾸면(`intent`: 포트폴리오수정) 새 초안(`base_portfolio_id`에 원래 포트폴리오)을 만들어 [2]~[5]를 다시 거침. 확인하면 기준 비중이 바뀐 새 버전(`origin`: `직접수정`)이 되고, 백테스트를 다시 승인해야 운용에 반영됨(잠정).

### [7] 동적 리밸런싱

국면이 전환되면 거시판단 로직이 **목표 종목·비중**을 정하고, 서버가 한도를 확인한 뒤 **자동으로 반영**함. 거시판단 로직(어떤 국면에서 무엇을 늘리고 줄일지, 어떤 종목으로 바꿀지)은 추후 구현함. 아래는 지금 정책에 있는 규칙으로 든 **예시**임.

**① 국면 전환 감지**

경기선행지수가 올라 경기가 `꺾임` → `좋아짐`으로 바뀌고, 확인 기간 동안 유지됨. 실운용에서는 LLM이 "11월 수출이 전년 대비 8.1% 늘었다"를 근거로 `확인됨`.

**② 목표 계산 (예시 규칙)**

1. **조건**: 경기 좋아짐 + 반도체IT 업종 늘어남(수출 +21.4%) → `regime_up_sector`
2. **대상 확인**: 포트폴리오에 반도체 ETF(`395270`)가 있음 → 적용
3. **조정**: 반도체 +3%p, 같은 주식 자산군의 S&P500 -3%p

목표 비중 = 기준 비중 + 지금 국면의 조정. 사용자가 직접 비중을 정한 ETF는 조정하지 않음(잠정). 예시는 비중을 정하지 않았으므로 둘 다 조정 대상.

**③ 한도 확인**

동적 조정 한도(기준 비중에서 10%p / 50% 중 좁은 쪽) 안인지 확인하고, 넘으면 한도까지만 반영함(잠정).

| ETF | 기준 비중 | 허용 범위 | 목표 비중 | 결과 |
|---|---|---|---|---|
| `395270` 반도체 | 9% | 4.5% ~ 13.5% | **12%** | 한도 안 |
| `360750` S&P500 | 51% | 41% ~ 61% | **48%** | 한도 안 |

종목을 새로 넣거나 빼는 경우에는 기준 비중이 0%이거나 0%가 되므로, 이 한도 방식을 그대로 쓸 수 없음. 종목 교체 시의 한도는 거시판단 로직과 함께 정함([미결 사항](#미결-사항)).

**④ 반영**

결과를 `adjustment.json`에 기록하고 포트폴리오의 **새 버전**을 만듦. 이전 버전은 덮어쓰지 않음.

revision 1 → revision 2 (`origin`: `동적조정`, `adj_20261201_pf_001`)

| ETF | 기준 비중 `base` | 목표 비중 `target` (rev 1 → rev 2) |
|---|---|---|
| `360750` S&P500 | 51% (그대로) | 51% → 48% |
| `395270` 반도체 | 9% (그대로) | 9% → 12% |
| 나머지 | 그대로 | 그대로 |

바뀐 목표 비중은 다음 장전 동시호가에 주문으로 맞춤. 사용자에게는 LLM이 쓴 조정 이유 문장(`adjustment_text`)으로 알림.

## 시장 분위기에 따른 대응

시장 분위기는 비중을 바꾸지 않고 **알림만** 줌. 이전에 있던 탐욕 시 리밸런싱 알림(위험자산이 목표보다 2%p 넘게 높으면)은 이중 밴드와 역할이 겹쳐서 없앰.

| 상태 | 대응 |
|---|---|
| 공포 | 사용자가 전략을 멈추거나 비중을 직접 줄이려 하면 "계획에 없던 매도"라고 경고함 |

## LLM이 하는 일 정리

| 작업 | 입력 | 출력 | 쓰는 곳 |
|---|---|---|---|
| `parse_request` | 사용자 메시지 | 칸 값 | 초안 |
| `evidence_check` | 뉴스·문서 | 국면 전환 근거와 판정 | 동적 전환 확인(실운용만) |
| `bok_policy` | 한국은행 의사록 등 | 통화정책 변화 여부 | 국면 지표 |
| `news_mood` | 뉴스 | 감성 점수, 테마 | 시장 분위기 |
| `adjustment_text` | 계산된 조정 결과 | 조정 이유 문장 | 동적 전환 알림 |

모든 호출은 `_record.json` 형식으로 기록함. 어떤 모델·프롬프트로, 어떤 문서를 보고, 검증을 통과했는지 나중에 추적할 수 있음.

## 미결 사항

| 항목 | 잠정안 |
|---|---|
| 거시판단 로직(국면 지표, 진입·해제 기준, 확인 기간, 국면별 목표 종목·비중) | 추후 구현. 지금 정책의 `regime_up_sector`, `regime_down_defense`는 예시 |
| 동적 전환으로 종목을 넣거나 뺄 때의 한도 | 정하지 않음. 지금 한도는 기준 비중 대비라 새 종목(기준 0%)에 쓸 수 없음 |
| 기본 자산군 비중 | 주식 60 / 채권 40. 근거(과거 성과, 손실 확률 등)를 정해 다시 확인 |
| 이중 밴드 폭, 반복 이탈 횟수 | 안쪽 5%p / 25%, 바깥 10%p / 50%. 반복 이탈 횟수는 정하지 않음 |
| 기준선 근접 구간 폭, 최대 보류 기간 | 정하지 않음 |
| "안전하게", "공격적으로" 같은 말을 어떻게 처리할지 | 처리하지 않음(기본값 사용). 필요하면 자산군 비중 프리셋(예: 안전하게 → 주식 30 / 채권 70)으로 바로 연결 |
| 백테스트에서 LLM 판단(근거 확인, 뉴스 감성)을 쓸지 | 쓰지 않고 지표 신호만 씀. 실운용 로직과 이 부분이 다르다는 점을 결과 화면에 밝힘 |
| 동적 전환이 사용자가 직접 정한 비중을 바꿀 수 있는지 | 바꾸지 않음. 생성된 부분만 조정 |
| 동적 조정이 한도를 넘을 때 | 한도까지만 반영 |
| 비중 표현(조금·보통·많이)을 HRP 비중에 반영하는 배수 | 0.5·1·1.5배 |
| 사용자가 고른 ETF가 백테스트 시작일에 없을 때 처리 | 정하지 않음. 투자 대상을 선정 조건으로 바꾸면서 백테스트가 공통 시작일이 아니라 2010년부터 돌아가므로 다시 정해야 함(`docs/backtest.md`) |
| 과거 시점에 슬롯 안에 후보가 없을 때 | 정하지 않음(`docs/backtest.md`) |
| 선정 조건과 숫자, 슬롯 분류 규칙 | 정하지 않음. 정해질 때까지 화이트리스트를 씀 |
| 위험자산에 통화(달러)를 넣을지 | 넣지 않음. 주식·원자재·리츠만 |
| 기준 비중을 HRP로 다시 만드는 주기 | 다시 만들지 않음(사용자가 수정할 때만). 상관계수·변동성은 몇 년이면 바뀌므로 연 1회 재생성도 검토. 정하면 백테스트도 같은 주기로 재생성해야 함 |
| 직접 수정 후 백테스트 재승인 | 필요함 |
