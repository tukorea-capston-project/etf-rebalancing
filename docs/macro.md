# 거시판단 운용 설계

확정된 전략을 운용하면서 매주 시장 국면을 판단하고, 국면이 바뀌면 종목·비중을 다시 정하는 방법을 정의합니다.
국면이 바뀐 날의 리밸런싱 실행은 `docs/rebalancing.md`, 백테스트에서의 처리(LLM 지표, 기준값과 과최적화)는 `docs/backtest.md`를 따릅니다.
뉴스 수집 코드는 `backend/app/news/`에 둡니다.

## 원칙

- 사용자가 확정한 전략은 **항상** 거시판단 운용으로 돌립니다. 국면 대응은 사용자가 전략에 적는 조건이 아니라 시스템이 합니다(`docs/strategy-schema.md`).
- 사람의 승인 없이 자동 실행하고, 알림과 전환 이력으로 남깁니다.
  - 백테스트와 실제 운용이 같은 로직이어야 하기 때문입니다. 사용자가 매번 고르는 방식은 과거로 재현할 수 없습니다.
- 사용자가 지정한 ETF, 자산군 비중, 현금 비중은 국면이 바뀌어도 그대로 지킵니다.
- 계산일까지 공개된 값만 씁니다.

## 두 층

운용 중에는 정적 층과 동적 층이 함께 돕니다.

| | 정적 층 | 동적 층 (거시판단) |
|---|---|---|
| 하는 일 | 시장 움직임으로 벌어진 비중을 현재 목표 비중으로 되돌립니다 | 국면이 바뀌면 목표 종목·비중 자체를 바꿉니다 |
| 언제 | 사용자가 고른 리밸런싱 조건(주기·밴드·혼합, `docs/strategy-schema.md`) | 매주 마지막 영업일 국면 판단 |
| 판단 근거 | 비중이 얼마나 벌어졌나 | 국면 지표의 Z-Score |

- 정적 리밸런싱(주기·밴드)으로는 국면을 다시 판단하지 않습니다.

## 국면 판단

- **정기**: 매주 마지막 영업일 종가 기준으로 판단합니다. 밴드 확인일과 같은 날입니다.
- **이벤트**: 주간 판단을 기다리기 어려운 큰 악재·호재에 대응합니다. 탐지 방법과 대응 방식은 미정입니다.
- **국면 분류**: 1차로 지표별 Z-Score 점수제로 합니다. 은닉 마코프 모형(HMM)은 같은 인터페이스로 추가하는 확장 과제입니다.
- **국면(예시)**: 금리 상승/하락, 환율 과열/안정, 고변동/저변동, 투자심리 공포/탐욕(`policy.macro.regimes`).
- **잦은 전환 방지**: 국면에 들어가는 기준과 빠져나오는 기준을 다르게 둡니다(히스테리시스). 이것으로만 막습니다.
- **기준값을 정하는 방식**: 진입·복귀 기준은 백테스트 결과를 보고 고르지 않고, 관례값·기본값(예: Z-Score ±1, 분위수)을 근거와 함께 미리 정해 씁니다. 견고성 표와 과최적화 확률(PBO)은 결과로만 보여 줍니다(`docs/backtest.md` 국면 판단 기준값과 과최적화).
- 자동 주문이 정지된 동안에도(`docs/trading.md` 안전장치) 국면 판단은 계속하고 기록만 남깁니다.

## 국면 지표

| 구분 | 국면 지표 | 출처 |
|---|---|---|
| 금리·환율 | 국고채 금리 변화율, 장단기 금리차, 원/달러 환율 | 한국은행 ECOS |
| 변동성 | VKOSPI | 미정 |
| 투자심리 | 신용융자 잔고, 투자자예탁금 | 금융투자협회 |
| 뉴스 | 뉴스 헤드라인 분위기 점수 (LLM) | 네이버 뉴스 API(실시간), 빅카인즈(과거 뉴스, 수동 수집) |
| 통화정책 | 금통위 의사록의 정책 방향 판정 (LLM) | 한국은행 |

- 공시는 국면 지표로 쓰지 않습니다.
- 지표마다 발표일을 두고, 발표일이 판단 기준일 이전인 값만 씁니다(`market.json`의 `released_at`).

### 뉴스

- 실시간 뉴스는 네이버 뉴스 API로 수집합니다.
- 백테스트용 과거 뉴스는 빅카인즈에서 수동으로 수집합니다. 빅카인즈 API는 비용이 커서 쓰지 않습니다.
- 헤드라인마다 LLM이 시장 관련 여부, 감성 점수, 테마를 매깁니다(`news_mood`, `docs/json-files.md`).

### LLM 지표

- 뉴스 분위기 점수와 금통위 의사록 판정은 LLM이 만듭니다. LLM은 이 두 지표와 사용자 문장 해석만 맡고, 국면 판단 자체는 서버 코드가 합니다.
- 백테스트에서도 LLM 지표를 씁니다. 미래 정보 누설을 다루는 방법은 `docs/backtest.md` LLM 지표와 미래 정보를 따릅니다.

## 국면 전환

국면이 바뀌면 묶음마다 새 국면에 맞는 ETF를 고르고 비중을 다시 계산해 자동으로 반영합니다. 예시는 `docs/json-flow.md` [7]에 있습니다.

1. **묶음별 ETF 선택 (속성 매칭)**: 묶음마다 후보 ETF의 속성(환헤지 여부, 듀레이션 등)이 새 국면에 얼마나 맞는지 점수를 매기고, 교체 비용을 뺀 점수(`RegimeFit − λ·SwitchCost`)가 가장 높은 ETF를 고릅니다. 사용자가 지정한 ETF는 바꾸지 않습니다.
2. **비중 다시 계산**: 고른 ETF로 HRP를 다시 돌리고 포트폴리오 생성과 같은 후처리를 합니다(`docs/strategy-schema.md` 포트폴리오 생성). 사용자가 정한 자산군 비중·현금 비중은 그대로 지킵니다.
3. **반영**: 결과가 새 현재 목표 비중이 됩니다. 국면 판단일을 계산일로 보고 전체 리밸런싱합니다(`docs/rebalancing.md`). 전략 버전은 만들지 않고 운용 상태와 전환 이력에 기록합니다(`docs/strategy-schema.md` 버전 관리).
4. **알림**: 어떤 지표가 기준을 넘었는지, 무엇을 사고팔았는지 알립니다(`docs/trading.md` 알림). 알림 문장은 LLM이 쓰지 않습니다.

## 투자심리 공포와 경고

투자심리 국면이 공포일 때, 사용자가 전략을 중지하거나 비중을 직접 줄이는 등 **계획에서 벗어난 매도**를 하려 하면 경고합니다(`policy.fear_warning`). 시스템이 국면 전환으로 하는 재구성에는 경고를 붙이지 않습니다.

## 미정

- 거시판단 작업의 코드 위치, 뉴스 수집 방식의 세부, 지표 수집·국면 판단 예약 작업의 실행 시각: #12
- Z-Score 기준 기간, 진입·복귀 임계값과 그 근거(정하는 방식은 위 "기준값을 정하는 방식")
- RegimeFit, λ, SwitchCost 정의와 ETF 속성 필드
- 국면 축과 상태(지금은 예시)
- VKOSPI 출처
- 이벤트(큰 악재·호재) 탐지와 대응
- 두 층의 우선순위: 국면 신호가 기준선 근처일 때 밴드 리밸런싱을 보류할지
- 운용을 시작하는 날 이미 어떤 국면이면 첫 목표 비중에 바로 반영할지
- LLM PC가 꺼져 있어 LLM 지표(뉴스 분위기 점수, 금통위 의사록 판정)를 받지 못할 때의 처리
- 국면 전환 알림 문장을 만드는 방식
