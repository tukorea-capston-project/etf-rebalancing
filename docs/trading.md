# 모의·실전투자 설계

KIS Open API로 모의투자·실전투자 주문을 내는 방식을 정의합니다. 모드 전환, KIS 자격 증명 보관, 안전장치, 알림을 다룹니다.
코드 구현은 `backend/app/trading/`에 둡니다. 주문 유형·시각·미체결 처리 등 주문 방식 자체는 #13에서 정합니다.

## 전제

- **실제 서비스를 가정한 설계**입니다. 여러 사용자가 각자 자기 KIS 계좌를 등록해 쓴다고 보고 설계합니다.
- 실제 서비스로 배포할 수 있게 만드는 것이 목표입니다. 개발·시연은 팀원 본인 계좌로 합니다.
- 모드, 자격 증명, 정지 상태는 모두 사용자에 속합니다. 사용자·인증 설계는 `docs/auth.md`를 봅니다.
- 사용자당 자동 운용 전략은 하나입니다(`docs/auth.md`).

## 모드

| 모드 | 계좌 | KIS REST | KIS WebSocket |
|---|---|---|---|
| 모의 | 사용자의 KIS 모의투자 계좌 | `https://openapivts.koreainvestment.com:29443` | `ws://ops.koreainvestment.com:31000` |
| 실전 | 사용자의 KIS 실전 계좌 | `https://openapi.koreainvestment.com:9443` | `ws://ops.koreainvestment.com:21000` |

- KIS 주소는 코드 상수(`backend/app/core/config.py`)로 고정하고 모드로 고릅니다. `.env` 등 설정값으로 주소를 받지 않습니다. 그래서 이 두 주소 외에는 쓸 수 없습니다.
- 백테스트, 모의투자, 실전투자는 같은 리밸런싱 로직을 씁니다(`docs/rebalancing.md`).
- 모드는 사용자 단위로 하나입니다.

## 모드 전환

사용자가 프론트엔드의 전환 버튼으로 바꿉니다. 실전을 언제 시작할지는 사용자가 정합니다. 모의투자 검증 기간을 강제하지 않습니다.

### 모의 → 실전

백엔드가 아래를 모두 확인해야 전환합니다. 프론트엔드 검사만으로 허용하지 않습니다.

1. 서버 실전 스위치(`REAL_TRADING_ENABLED`)가 켜져 있습니다.
2. 사용자의 실전 자격 증명이 등록되어 있고 검증을 통과했습니다.
3. 사용자가 비밀번호를 다시 입력했습니다.
4. 사용자가 "실제 돈으로 사람의 승인 없이 자동 주문이 나간다"는 경고를 확인했습니다.

### 실전 → 모의

- 바로 전환합니다. 아직 체결되지 않은 실전 주문은 취소합니다.

### 공통

- 전환해도 보유 종목을 옮기지 않습니다. 주문할 계좌가 바뀌는 것이므로, 다음 리밸런싱은 새 계좌의 실제 잔고에서 시작합니다.
  - 예: 빈 실전 계좌로 전환하면 첫 리밸런싱에서 전략에 정한 금액만큼 목표 비중대로 매수합니다.
- 전환 이력(시각, 방향)을 남깁니다.

## 자격 증명

### 등록

- 사용자가 모의·실전 각각의 앱키, 시크릿, 계좌번호(앞 8자리 + 상품코드 2자리)를 등록합니다. KIS 앱키는 계좌 주인이 KIS 개발자센터에서 직접 발급받습니다.
- 등록할 때 접근 토큰을 발급해 보며 검증합니다. 발급할 때마다 계좌 주인에게 알림톡이 갑니다.
- KIS 자격 증명은 `.env`에 두지 않습니다. KIS 클라이언트는 자격 증명을 인자로 받고, 설정에서 읽지 않습니다.

### 저장

- 앱키, 시크릿, 계좌번호, 접근 토큰은 애플리케이션에서 암호화해 DB에 저장합니다(봉투 암호화: 값은 데이터 키로, 데이터 키는 마스터키로 암호화).
- 마스터키는 DB에 두지 않습니다. DB가 유출되어도 마스터키 없이는 복호화할 수 없게 하려는 것입니다.

| 실행 위치 | 마스터키 | 설정 |
|---|---|---|
| AWS EC2 | AWS KMS. EC2의 IAM 역할로만 쓸 수 있습니다 | `CREDENTIAL_KEY_PROVIDER=kms`, `KMS_KEY_ID` |
| 팀원 PC(개발·테스트) | `.env`의 로컬 키 | `CREDENTIAL_KEY_PROVIDER=local`, `CREDENTIAL_LOCAL_KEY` |

- 서버 실전 스위치를 켜려면 마스터키가 KMS여야 합니다. 로컬 키와 함께 켜면 서버가 시작되지 않습니다.
- 서비스 DB의 자격 증명은 KMS로 암호화되어 있어 팀원 PC 백엔드에서는 복호화할 수 없습니다. 팀원 PC에서 KIS를 호출해 보려면 개발 서버를 테스트 DB에 붙이고(`docs/infra.md`) 자기 모의투자 자격 증명을 등록합니다.

### 노출 금지

- 원문을 API 응답으로 돌려주지 않습니다. 화면에는 마스킹해 보여 줍니다(예: `****1234`).
- 로그, 예외 메시지, 알림에 원문을 남기지 않습니다. 코드에서는 `SecretStr`로 다룹니다.

### 삭제

- 사용자가 삭제하면 즉시 지웁니다. 캐시된 접근 토큰도 함께 지웁니다.
- 실전 자격 증명을 지우면 모의로 전환합니다(미체결 실전 주문 취소).

### 접근 토큰

- 사용자·모드별로 캐시해 재사용하고 요청마다 새로 발급하지 않습니다.
- 유효기간은 1일이고, 재발급은 1분에 1회로 제한되며, 발급할 때마다 알림톡이 발송됩니다.

## 주문 실행

- 모의·실전 모두 리밸런싱 조건이 되거나 국면이 바뀌면 **자동으로 주문**합니다. 사람의 승인 단계는 없습니다. 결과는 알림으로 보냅니다.
- 금액 상한(투입 금액, 1회 주문 금액)은 두지 않습니다. 안전장치는 아래 "안전장치"의 항목입니다.
- 주문 유형, 주문 시각, 미체결·부분 체결, 분배금 입금 확인 후 재투자 흐름은 #13에서 정합니다.
  - 주문 시각(잠정): 계산일 다음 영업일 장 시작 전 동시호가(08:40)에 냅니다.
  - 최소 주문 금액은 `docs/rebalancing.md` 주문 수량 계산을 따릅니다.
- 주문 전 점검(잠정, `portfolio.trading.pre_order_checks`)
  - ETF 가격이 NAV보다 1% 넘게 비싸면 보류합니다.
  - 거래정지 종목은 건너뜁니다.
  - 잔고를 확인합니다.
- 호출 간격을 조절하고, 초당 호출 초과 오류(`EGW00201`)가 나면 재시도합니다. 모의투자는 실전보다 호출 제한이 낮습니다.

## 안전장치

### 서버 실전 스위치

- `.env`의 `REAL_TRADING_ENABLED`입니다. 기본값은 `false`입니다.
- `false`면 실전 주문을 보내지 않고, 실전 전환도 막습니다. 이미 실전 모드인 사용자의 자동 주문은 멈추고 알립니다.
- AWS EC2에서만 켭니다. 팀원 PC에서는 항상 `false`입니다.

### 이상 감지 시 주문 중단

주문을 보내기 직전에 검사합니다. 하나라도 걸리면 그 회차 주문을 **하나도 보내지 않고**, 그 사용자의 자동 주문을 정지 상태로 바꾼 뒤 알립니다. 사용자가 확인하고 재개해야 다시 자동 주문합니다.

| 구분 | 검사 |
|---|---|
| 데이터 | 계산일 종가가 없는 보유·목표 ETF가 있음 |
| 전략 | 목표 비중 합계가 100%가 아니거나, 전략 스키마 검증에 실패함 |
| 계좌 | KIS 잔고(보유 수량, 현금)와 내부 기록이 다름 |
| 사용자 기준 | 사용자가 정한 기준을 넘는 주문임 |

- 사용자 기준값은 사용자가 자유롭게 정합니다. 서버가 강제하는 최대치는 없습니다.

### 긴급 중지

- 사용자별 버튼입니다. 누르면 그 사용자의 자동 주문을 즉시 멈추고, 미체결 주문을 취소합니다. 모의·실전 모두 적용합니다.
- 이상 감지와 같은 정지 상태를 쓰고, 정지 사유(이상 감지 / 긴급 중지 / 서버 스위치)를 구분해 남깁니다.
- 재개는 사용자가 직접 합니다.

## 알림

- 알림은 이메일로 보냅니다.
- 알림 대상: 주문 결과(체결, 미체결), 국면 전환(어떤 지표가 기준을 넘었는지, 무엇을 사고팔았는지), 공포 경고, 이상 감지 정지, 긴급 중지, 서버 스위치로 인한 정지, 모드 전환, 접근 토큰 발급 실패.
- 알림에 자격 증명 원문을 넣지 않습니다.

## 미정

- 이메일 발송 수단(SMTP, AWS SES 등)
- 이상 감지의 사용자 기준 항목과 기본값(예: 1회 주문 금액이 평가금액의 몇 %를 넘으면 중단)
- 암호화 라이브러리와 로컬 키 형식: 구현 때 정합니다.
- 주문 방식(#13): 주문 유형(지정가/시장가), 주문 시각 확정(잠정 08:40), 미체결·부분 체결 처리, 매도·매수 체결 확인 방법, 분배금 입금 확인과 재투자 흐름
- 모의·실전투자의 계산일 종가 출처(#13). KRX 데이터는 다음 영업일 오전 8시경 갱신되므로 계산일 장 마감 직후에는 없습니다(`docs/architecture.md`). KIS 시세 조회 등을 검토합니다
- 주문 전 점검(잠정)과 "이상 감지 시 주문 중단"의 관계. 잔고 확인이 양쪽에 있습니다
