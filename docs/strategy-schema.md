# 전략 스키마 설계

사용자의 자연어 입력을 변환해 만드는 "전략"이 무엇을 담는지, 어떤 제약을 지켜야 하는지 정의합니다.
코드 구현은 `backend/app/strategy/`의 Pydantic 모델로 합니다.

## 기본 개념

전략은 **사용자의 요구**와 그 요구로 만든 **포트폴리오(종목·비중)**를 담습니다. 사용자가 확인해야만 확정됩니다.

시장 신호에 따라 비중을 바꾸는 조건(예: "20일 이평선 아래면 채권으로")은 사용자가 전략에 적는 값이 아닙니다. 국면에 따른 대응은 시스템의 **거시판단 운용**이 합니다([거시판단 운용](#거시판단-운용)).

| 구분 | 의미 | 바뀌는 때 |
|---|---|---|
| 전략 비중 | 전략을 확정할 때 만든 종목·비중 | 사용자가 전략을 직접 수정할 때만 |
| 현재 목표 비중 | 지금 리밸런싱이 따르는 종목·비중. 전략이 아니라 운용 상태에 둡니다 | 국면이 바뀔 때 |

## 전략의 구성 요소

1. 자산군·현금 비중
2. 묶음: 넣거나 뺄 ETF 묶음
3. 직접 지정한 종목
4. 리밸런싱 조건
5. 금액: 초기 투자금, 정기 적립

사용자가 말하지 않은 비중과 종목은 비워 두고 시스템이 계산합니다([포트폴리오 생성](#포트폴리오-생성)). 리밸런싱 조건과 금액은 필수 값이라 비어 있으면 되묻습니다([자연어 → 전략 변환](#자연어--전략-변환)).

### 1. 자산군·현금 비중

- 자산군은 묶음보다 큰 상위 묶음입니다(예: 주식·채권·대체·현금성).
- 사용자가 자산군 비중을 말하면 그대로 씁니다. 말하지 않으면 HRP가 자산군 배분까지 정합니다.
- **현금**도 하나의 자산입니다. 사용자가 현금 비중을 말하면 먼저 떼어 두고, 말하지 않으면 0%입니다. 현금은 HRP 계산에 넣지 않습니다.

### 2. 묶음

- 묶음(슬롯)은 투자 대상 ETF의 분류(category)·세부 묶음(group)입니다.
- 기본 묶음 세트(설정 파일)에서 시작해, 사용자 문장에 나온 묶음을 더하거나 뺍니다. 묶음은 최대 10개입니다.

### 3. 직접 지정한 종목

- 사용자가 지정한 ETF는 고정합니다. 포트폴리오 생성과 국면 전환에서 바꾸지 않습니다.
- 지정할 수 있는 ETF는 선정 조건을 통과한 ETF뿐입니다.

### 비중 제약

- 투자 대상은 선정 조건(`backend/config/`)을 통과한 ETF와 현금입니다.
- 비중은 **1%p 단위 정수**이고, 합계는 현금을 포함해 **100%** 이어야 합니다.
- ETF 제약
  - 종목 수는 **최대 10개**
  - 종목당 **최소 5%**
- 현금은 위 제약의 예외입니다. 종목 수에 세지 않고, 최소 비중이 없습니다(0% 가능). 단주 처리로 남는 자투리 현금도 현금 비중에 포함됩니다.

### 4. 리밸런싱 조건

국면이 유지되는 동안 목표 비중으로 되돌리는 조건입니다. 아래 중 하나를 고르며, 사용자 전략에 정의된 대로 따릅니다.

| 조건 | 내용 |
|---|---|
| 주기 | 정해진 날짜에 리밸런싱 |
| 비중 이탈 밴드 | 목표 비중에서 밴드를 벗어나면 리밸런싱 |
| 주기 + 밴드 혼합 | 주기마다 확인하되 밴드를 벗어난 경우에만 리밸런싱 |

적립금은 조건과 관계없이 들어오면 부족한 자산부터 매수하는 고정 규칙을 따릅니다. 분배금은 항상 같은 ETF에 재투자합니다. 실행 방법은 `docs/rebalancing.md`를 따릅니다.

#### 주기

- 주기는 **월·분기·반기·연** 중 하나입니다. 사용자가 일자를 지정하고, 분기·반기·연은 시작 월도 지정합니다.
- 그 달에 지정 일자가 없으면(예: 31일) 그 달 말일로 합니다.
- 휴장일이면 다음 영업일로 미룹니다.

#### 비중 이탈 밴드 (5/25형)

- 사용자는 **절대 폭(%p)**과 **상대 폭(%)** 두 값을 정합니다. 자산마다 둘 중 **더 좁은 쪽**을 밴드로 씁니다.
- 기본값은 **5%p / 25%**입니다.
  - 목표 60% → 절대 ±5%p, 상대 ±15%p → 55~65%
  - 목표 10% → 절대 ±5%p, 상대 ±2.5%p → 7.5~12.5%
- 이탈 여부는 **주 1회**, 매주 마지막 영업일 종가로 확인합니다. 국면 판단과 같은 날입니다.
- 밴드를 벗어나면 **벗어난 자산만 목표 비중으로** 되돌립니다. 그 차액은 나머지 자산에서 조정합니다.

### 5. 금액

- 초기 투자금과 정기 적립은 전략에 포함합니다.
- 정기 적립은 **매월**만 지원하며, 일자와 금액을 지정합니다. 일자 규칙(없는 날은 말일, 휴장일은 다음 영업일)은 리밸런싱 주기와 같습니다.

## 포트폴리오 생성

비어 있는 비중과 종목은 코드가 계산합니다. LLM은 숫자를 만들지 않습니다.

1. 자산군 비중: 사용자가 말했으면 그대로, 아니면 HRP가 정합니다
2. 묶음 고르기: 기본 묶음 세트 ± 사용자 문장의 묶음
3. 묶음별 후보: 그 시점에 선정 조건을 통과한 ETF
4. 종목 선택: 사용자가 지정한 ETF는 고정하고, 나머지 묶음마다 대표 하나를 고릅니다. 대표들끼리의 **최대 상관계수가 가장 작은 조합**을 찾습니다(minimax)
5. 비중 계산: HRP. 사용자가 자산군 비중을 줬으면 자산군 안에서만 나눕니다
6. 후처리: 5% 미만은 5%로 올리고 나머지를 비례 축소한 뒤, 1%p 단위로 최대잔여법 반올림
7. 스키마 검증 → 사용자 확인

| 경우 | 자산군 비중 | 종목 선택 | 비중 계산 |
|---|---|---|---|
| 둘 다 지정 안 함 | HRP | minimax | HRP |
| 비중만 지정 | 사용자 | minimax | 자산군 안에서 HRP |
| 종목만 지정 | HRP | 사용자 | HRP |
| 둘 다 지정 | 사용자 | 사용자 | 스키마 검증만 |

- 투자성향(안정형~공격형) 개념과 성향별 템플릿은 쓰지 않습니다.
- 종목·비중 계산에 쓰는 기간(선정 기간)과 백테스트 기간을 나눕니다(`docs/backtest.md`).

## 거시판단 운용

사용자가 확정한 전략은 항상 거시판단 운용으로 돌립니다. 사람의 승인 없이 자동 실행하고, 알림과 전환 이력으로 남깁니다.

- **정기**: 매주 마지막 영업일 종가로 국면을 판단합니다.
  - 국면이 바뀌면 묶음마다 그 국면에 맞는 ETF를 속성 매칭 점수(`RegimeFit − λ·SwitchCost`)로 고르고, 비중은 HRP로 다시 계산합니다. 이 결과가 새 현재 목표 비중이 됩니다.
  - 국면이 유지되는 동안은 사용자가 고른 리밸런싱 조건으로 현재 목표 비중에 되돌립니다.
  - HRP는 포트폴리오를 만들 때와 국면이 바뀔 때만 계산합니다.
  - 잦은 전환은 히스테리시스(진입·복귀 기준을 다르게 둠)로만 막습니다.
  - 정적 리밸런싱(비중 이탈)으로는 국면을 다시 판단하지 않습니다.
- **이벤트**: 큰 악재·호재에 대응합니다. 탐지 방법과 대응 방식은 미정입니다.
- 사용자가 지정한 ETF, 자산군 비중, 현금 비중은 국면이 바뀌어도 그대로 지킵니다.
- 국면 분류는 1차로 지표별 Z-Score 점수제로 합니다. HMM은 같은 인터페이스로 추가하는 확장 과제입니다. 계산일까지의 데이터만 씁니다.
- 국면 지표: 국고채 금리 변화율, 장단기 금리차, 원/달러 환율(ECOS), VKOSPI, 신용융자 잔고·투자자예탁금(금융투자협회), 뉴스 분위기 점수(LLM), 금통위 의사록 판정(LLM). 공시는 쓰지 않습니다.

## 버전 관리

- 전략은 버전으로 관리합니다. 덮어쓰지 않습니다.
- 사용자가 전략을 직접 수정하면 새 버전을 만듭니다.
- 국면 전환은 전략 버전을 만들지 않습니다. 현재 목표 비중은 운용 상태에 두고, 바뀔 때마다 전환 이력으로 기록합니다.

## 자연어 → 전략 변환

- LLM은 사용자 문장에서 값을 **선택지 목록(카탈로그)** 안에서 고르고 설명 문장을 쓰는 일만 합니다. 비중, 종목코드 같은 숫자는 코드가 계산합니다. LLM 출력은 JSON 스키마로 형식을 강제합니다.
- LLM 출력은 이 스키마로 검증한 뒤, 사용자가 확인해야만 확정합니다.
- 리밸런싱 조건·투자 금액 같은 **필수 값이 비면** 사용자에게 되묻습니다. 되물을 때는 선택지를 3개 정도 함께 제시합니다. 비중과 종목은 되묻지 않고 비워 두면 시스템이 계산합니다.
- 스키마로 **표현할 수 없는 요청**은 근사치를 제안한 뒤 확인을 받습니다. 예: 지원하지 않는 조건, 선정 조건 밖 종목. 원래 요청과 무엇이 다른지 표시합니다.

## 미정

- Pydantic 모델의 필드 이름과 구조
- 자산군 목록, 기본 묶음 세트 구성, 선정 기간 길이, minimax 탐색 방법
- "둘 다 지정"이 ETF별 비중까지 사용자가 주는 경우인지
- 백테스트한 포트폴리오(선정 기간 데이터)와 실제 운용 포트폴리오(최근 데이터)가 다를 때의 처리·표시
- 거시판단: 이벤트 탐지·대응, Z-Score 기준 기간과 진입·복귀 임계값(정하는 방식은 `docs/backtest.md`), RegimeFit·λ·SwitchCost 정의와 ETF 속성 필드, VKOSPI 출처. 상세는 #12
- 전략 이름, 설명 등 메타데이터
