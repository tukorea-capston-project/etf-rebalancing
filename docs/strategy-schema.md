# 전략 스키마 설계

사용자의 자연어 입력을 변환해 만드는 "전략"이 무엇을 담는지, 어떤 제약을 지켜야 하는지 정의한다.
코드 구현은 `backend/app/strategy/`의 Pydantic 모델로 한다.

## 기본 개념

전략은 **고정 목표 비중**을 가진다. 시장 신호에 따라 목표 비중이 자동으로 바뀌는 방식(예: "20일 이평선 아래면 채권으로")은 리밸런싱이 아니라 전술적 자산배분(TAA)이므로 전략 스키마로 표현하지 않는다.

대신 시스템의 **거시판단 로직**이 목표 비중 조절을 **제안**하고, 사용자가 수락할 때만 반영한다.

| 구분 | 의미 | 누가 정하나 |
|---|---|---|
| 기준 비중 (SAA) | 사용자가 직접 확정한 목표 비중 | 사용자 |
| 현재 목표 비중 | 지금 리밸런싱이 따르는 비중. 기준 비중이거나, 수락한 제안이 반영된 비중 | 사용자 (제안 수락 포함) |

## 전략의 구성 요소

1. 목표 비중
2. 리밸런싱 조건
3. 금액: 초기 투자금, 정기 적립
4. 거시판단 제안 한도

### 1. 목표 비중

- 투자 대상은 화이트리스트(`backend/config/`) 안의 ETF와 **현금**이다. 현금도 하나의 자산으로 비중을 지정할 수 있다.
- 비중은 **1%p 단위 정수**이고, 합계는 현금을 포함해 **100%** 이어야 한다.
- ETF 제약
  - 종목 수는 **최대 10개**
  - 종목당 **최소 5%**
- 현금은 위 제약의 예외다. 종목 수에 세지 않고, 최소 비중이 없다(0% 가능). 단주 처리로 남는 자투리 현금도 현금 비중에 포함된다.

### 2. 리밸런싱 조건

아래 조건 중 하나를 고르며, 사용자 전략에 정의된 대로 따른다.

| 조건 | 내용 |
|---|---|
| 주기 | 정해진 날짜에 리밸런싱 |
| 비중 이탈 밴드 | 목표 비중에서 밴드를 벗어나면 리밸런싱 |
| 주기 + 밴드 혼합 | 주기마다 확인하되 밴드를 벗어난 경우에만 리밸런싱 |

적립금은 조건과 관계없이 들어오면 부족한 자산부터 매수하는 고정 규칙을 따른다. 분배금은 항상 같은 ETF에 재투자한다. 실행 방법은 `docs/rebalancing.md`를 따른다.

#### 주기

- 주기는 **월·분기·반기·연** 중 하나다. 사용자가 일자를 지정하고, 분기·반기·연은 시작 월도 지정한다.
- 그 달에 지정 일자가 없으면(예: 31일) 그 달 말일로 한다.
- 휴장일이면 다음 영업일로 미룬다.

#### 비중 이탈 밴드 (5/25형)

- 사용자는 **절대 폭(%p)**과 **상대 폭(%)** 두 값을 정한다. 자산마다 둘 중 **더 좁은 쪽**을 밴드로 쓴다.
- 기본값은 **5%p / 25%**다.
  - 목표 60% → 절대 ±5%p, 상대 ±15%p → 55~65%
  - 목표 10% → 절대 ±5%p, 상대 ±2.5%p → 7.5~12.5%
- 이탈 여부는 **주 1회**, 매주 마지막 영업일 종가로 확인한다.
- 밴드를 벗어나면 **벗어난 자산만 목표 비중으로** 되돌린다. 그 차액은 나머지 자산에서 조정한다.

### 3. 금액

- 초기 투자금과 정기 적립은 전략에 포함한다.
- 정기 적립은 **매월**만 지원하며, 일자와 금액을 지정한다. 일자 규칙(없는 날은 말일, 휴장일은 다음 영업일)은 리밸런싱 주기와 같다.

### 4. 거시판단 제안 한도

- 사용자는 제안 한도를 전략에 정해 둔다. 제안을 받지 않도록 설정할 수도 있다.
- 한도는 **기준 비중(SAA)**에서 잰다. 현재 버전에서 재지 않는다. 그래야 제안을 여러 번 수락해도 사용자가 정한 성향에서 한도 이상 벗어나지 않는다.
- 한도도 5/25형이다. 절대 폭과 상대 폭 중 좁은 쪽을 쓰고, 기본값은 **10%p / 50%**다.
  - 기준 60% → 50~70%
  - 기준 10% → 5~15%
- 사용자는 자산별로 한도를 바꿀 수 있다.

## 버전 관리

- 전략은 버전으로 관리한다. 덮어쓰지 않는다.
- 거시판단 제안을 수락하면, 목표 비중을 바꾼 **새 버전**을 만든다. 기준 비중(SAA)은 그대로다.
- 사용자가 비중을 직접 수정하면 새 버전을 만들고, 기준 비중(SAA)도 그 값으로 갱신한다.

## 자연어 → 전략 변환

- LLM 출력은 이 스키마로 검증한 뒤, 사용자가 확인해야만 확정한다.
- 입력에서 **빠진 값**은 사용자에게 되묻는다. 되물을 때는 선택지를 3개 정도 함께 제시한다.
- 스키마로 **표현할 수 없는 요청**은 근사치를 제안한 뒤 확인을 받는다. 예: 지원하지 않는 조건, 화이트리스트 밖 종목. 원래 요청과 무엇이 다른지 표시한다.
