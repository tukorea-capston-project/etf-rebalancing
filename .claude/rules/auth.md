# 사용자·인증 규칙

상세 설계는 `docs/auth.md`를 따릅니다. 로직을 바꾸기 전에 그 문서를 읽고, 설계가 바뀌면 문서도 함께 고칩니다.

- 인증은 서버 세션입니다. 세션은 DB에 저장하고, 세션 ID만 쿠키로 줍니다. JWT를 쓰지 않습니다.
- 세션 쿠키는 `HttpOnly`, `Secure`로 둡니다.
- 프론트엔드와 API는 같은 오리진입니다(CloudFront가 `/api/*`를 EC2로 전달). CORS를 열거나 크로스 도메인 쿠키(`SameSite=None`)를 쓰지 않습니다.
- 비밀번호는 해시로만 저장합니다. 원문을 DB, 로그, 예외 메시지, API 응답에 남기지 않습니다.
- 모드, KIS 자격 증명, 정지 상태, 전략, 포트폴리오는 모두 사용자에 속합니다. 다른 사용자의 데이터를 조회·수정할 수 없게 소유자를 검사합니다.
- 자동 운용 전략은 사용자당 하나입니다. 전략은 여러 개 만들고 백테스트할 수 있습니다.
